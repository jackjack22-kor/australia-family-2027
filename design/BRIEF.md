# 리디자인 브리프 · A+ (탑승권 + 위젯)

## 0. 목표와 원칙
현재 앱은 기능과 접근성 기준은 대부분 통과했지만, 화면이 개성 없는 관리자 대시보드처럼 보인다. 원인은 다음과 같다.
- 카드 모양이 4종, 버튼 스타일이 4종 이상 섞여 있다.
- 위계가 평평하다.
- 사진이 홈 맨 아래로 밀려나 있다.
- 도시 색이 일부 화면에서만 쓰인다.

목표는 `design/mockups`의 A+ 시안을 실제 앱으로 옮기는 것이다.

- **한 가지 카드 언어**: 흰 면, 모서리 20px, 그림자·테두리 없음, 바탕(--bg)과의 명도 차로만 구분한다. 예외는 탑승권 카드(--pass-bg)와 선택 상태(2px --primary 테두리) 둘뿐이다.
- **버튼은 3종**: 주 버튼(--primary 채움, 52px), 톤 버튼(--surface-3 바탕 + --primary 글자), 추가 버튼(점선 테두리, "+ …"). 텍스트 링크는 보조 이동에만 쓴다.
- **도시 색을 끝까지 일관되게**: 홈 구간 막대, 비교 날짜 막대, 일정 그룹 머리, 날짜 스트립 점, 지도·방문지 타일에 같은 색을 쓴다.
- **상태 표시는 배지 하나로**: 확정(초록) / 대기(노랑) / 미예약·미정(회색) / 조치 필요(코랄). 금액이 추정이면 금액 옆에 점선 테두리 "추정" 배지를 단다. 문장 끝마다 "확인 필요"를 반복하지 않는다.
- **한글 줄바꿈**: 전역 `word-break: keep-all; overflow-wrap: anywhere;`. 시안 렌더링에서 "수수/료"처럼 단어가 쪼개진 곳이 있으니 반드시 적용한다.
- **숫자**: `font-variant-numeric: tabular-nums`.

## Phase 0 · 현황 파악과 구조 정리 (화면 변화 없음)
목적은 이후 작업을 안전하게 만드는 것이다. 이 Phase가 끝나도 **사용자가 보는 화면과 동작은 이전과 같아야 한다.**

1. 로컬 폴더 상태를 확인한다: `git status`, `git log -5`, 원격과의 차이(`git fetch` 후 비교). 커밋되지 않은 변경이 있으면 작업 전에 사용자에게 알린다.
2. 기준 스크린샷을 만든다: `npm install` → `npx playwright install chromium` → `npm run shots` → `.shots`를 `.shots-baseline`으로 복사한다(커밋 안 함, .gitignore에 포함됨).
3. 저장 데이터 픽스처를 만든다: 현재 앱에서 메모, 체크 2~3개, 호텔 1곳 예약 상태, 항공 예약번호(가짜), 환율, 현지 예산 1건을 입력한다. 그 localStorage 값을 `tools/fixtures/storage.json`으로 저장한다(가짜 값만).
4. 파일을 분리한다.

   | 파일 | 내용 |
   |---|---|
   | `index.html` | 마크업 골격 |
   | `assets/app.css` | 스타일 |
   | `assets/data.js` | `TRIP` 원본 데이터 |
   | `assets/app.js` | 로직·렌더링 |
   | `assets/img/sydney.jpg` | base64 표지 사진을 파일로 |

   - 재정의된 함수와 CSS 변수는 **최종 정의만 남기고** 정리한다. 동작이 바뀌면 안 된다.
5. **HTML 사본 받기** 기능이 분리 후에도 오프라인 단일 파일로 동작하게 고친다. 내보낼 때 CSS·JS·이미지를 인라인으로 넣는다.
6. 검증한다.
   - `npm run shots` 결과를 `.shots-baseline`과 비교해 화면 차이가 없음을 확인한다.
   - `--fixture` 점검에서 입력값이 그대로 보이는지 확인한다.
   - 백업 내보내기 → 가져오기 왕복, HTML 사본 열기를 확인한다.
7. README의 "배포 파일과 호환성" 절을 새 구조에 맞게 고친다.

### 데스크톱(≥1024px)
시안은 모바일만 있으므로 아래 규칙으로 확장한다.
- 콘텐츠 최대 폭 1120px, 가운데 정렬.
- 하단 탭바 대신 앱 바 안에 가로 탭을 둔다.
- 홈: 2열. 왼쪽은 사진(16:9, r20) + 제목·구간 막대 + 결정 카드, 오른쪽은 위젯 2×2 + 탑승권.
- 하루 상세: 왼쪽 일정(요약 카드 + 방문지), 오른쪽 sticky 지도 + 오늘 밤 숙소.
- 비교: 여행안 카드 + 날짜 막대는 전체 폭. 비교표와 귀국 도시는 2열.
- 768px은 모바일 레이아웃을 최대 폭 640으로 가운데 정렬하고, 하단 탭바를 유지한다.

### 다크 모드
tokens.css의 다크 값을 쓴다. 수동 선택(`data-theme`)도 같은 값으로 지원한다. 탑승권은 다크에서도 어두운 남색(--pass-bg)을 유지한다. 사진 위 칩은 라이트·다크 동일하다.

## 로직·콘텐츠 수정 (L)
- **L1 미정 집계 분리.** 현재 "미정 46개"는 일자별 식비·입장료·투어비 빈칸(15일 × 3)까지 센다. 아래 둘로 나눈다.
  - "결정이 필요한 미정": 항공·숙소·이동 비용 중 값이 없는 것.
  - "현지 예산 입력 n/15일": 따로 센다.
  - 비교표·경비·위젯 모두 이 기준을 따른다.
- **L2 예약 상태와 금액 확실성 분리.** 예약 상태(발권 확정·대기·미예약)와 금액(실결제·추정·미정)을 별개 필드로 보여 준다.
  - 예: 2안의 KE408 2/18은 **발권 확정**이고, 금액 약 110만원은 **추정**이다(실결제액 입력 시 확정으로 전환).
  - 2안 확정 비용이 0원으로만 보이지 않게 한다.
- **L3 1박당 비용.** 그 안의 핵심 항공 비용(출국·귀국)이 미정이면 1박당 비용 대신 "출국편 입력 후 비교"를 표시한다.
- **L4 손익분기 문장.** 기존 계산을 유지하되 "2안 출국편이 4인 합계 약 n만원 이하라면 비용은 2안이 유리합니다" 한 문장으로 쓴다. 숫자는 만원 단위로 반올림한다.
- **L5 항공 카드 통합.** 같은 편명·같은 구간의 클래스별·날짜별 레코드는 카드 하나 안의 행으로 합친다.
- **L6 빈 선택 필드 숨김.** "미정 · 미정 3개"처럼 비어 있는 선택 정보를 일정 화면에 나열하지 않는다. 입력 진입점은 하루 상세의 톤 버튼이나 추가 버튼 하나로 둔다.
- **L7 반복 일러스트 제거.** 숙소 카드의 도시 일러스트는 쓰지 않는다. 아이콘 타일로 대체한다.
- **L8 (사용자 확인 필요)** 준비 항목 "학교 일정 확인"과 "학교 교외체험학습 신청"이 중복으로 보인다. 병합 여부를 사용자에게 묻고, 병합 시 기존 완료 상태(`done.ID`)를 보존한다.
